REAL-TIME EXAMPLE

How one request travels through the system

One request, end to end
USER REQUEST
“Find an EV charging spot near the entrance, tell me the current price and guide me there.”
01

Supervisor understands the sentence

It sees three different jobs hidden inside one sentence: find a live EV spot, read pricing policy, and build a route.

occupancy + knowledge + navigation
02

LangGraph fans the work out

The three specialists receive the same request context, but each one focuses on its own responsibility.

Send(agent_node, task)
03

Occupancy reads live state

The agent checks SQLite and returns EV spots that are currently available, then sorts them by distance to the entrance.

status == "available" and spot_type == "ev"
04

Knowledge agent uses RAG

It searches the facility documents, reranks matching chunks and returns the policy text needed for the price answer.

query → retrieve → rerank → answer
05

Navigation builds the route

It uses parking metadata to create a clear POC route such as Gate A → floor → row → spot.

entrance → floor → row → spot
06

Synthesis explains the result

The final agent combines the three outputs, trusts deterministic live state, cites RAG sources when present and avoids inventing a reservation.

specialist outputs → grounded response
